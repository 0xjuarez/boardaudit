# Contributing

## Scope

boardaudit is an authorized-use audit tool. Contributions must keep
that scope: read-only acquisition and analysis of devices the
contributor owns or is authorized to audit. Do not add exploitation,
bypass, credential extraction, or network attack features.

## How to contribute

1. Fork the repository and create a branch for your change.
2. Install the development dependencies: `python3 -m pip install ".[dev]"`
3. Run the tests before and after your change: `python3 -m pytest -q`
4. Keep changes small and focused. One change per pull request.
5. Do not include real secrets, firmware images from devices you
   do not own, endpoints, payloads, or exploit code in a pull
   request, an issue, or a test fixture. Test fixtures must be
   generated by the tests themselves.
6. Do not add a dependency without explaining why the standard
   library cannot do the job. Hardware tools (esptool, pyserial)
   stay optional.

## Code style

- Python 3.11 or later, standard library preferred.
- No `shell=True`, no `eval` or `exec`, no string interpolation
  into commands. Subprocess calls use argument lists only.
- Validate paths, ports, board ids, and scan ids before use.
- Escape firmware-derived text in any output. Never write a
  full secret value to a report, a log, or standard output.

## Reporting a problem

- For a bug, open an issue with the command you ran, the
  boardaudit version, and the error output with any secrets
  removed.
- For a security problem, follow `SECURITY.md`. Do not open a
  public issue for a vulnerability.
